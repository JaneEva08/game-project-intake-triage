# Сценарий записи видео VPk04.1

В задании для локального варианта указаны два ролика: демонстрация продукта на 2–3 минуты и защита проекта на 5–7 минут. Запиши их отдельно. Скриншоты в `report.md` иллюстрируют интерфейс, но по материалам задания не заменяют видеоролик.

## Подготовка перед записью

1. Открой папку проекта `VPk04.1-game-project-intake-triage` в Проводнике.
2. Запусти PowerShell в этой папке: в адресной строке Проводника набери `powershell` и нажми **Enter**.
3. Активируй окружение и запусти сервис:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   uvicorn app.main:app --reload --port 8000
   ```

   Если виртуальное окружение ещё не создано, один раз выполни команды установки из README. Если порт занят — останови только свой старый экземпляр `uvicorn` сочетанием **Ctrl+C**, затем запусти на свободном порту и согласуй `PUBLIC_BASE_URL` в локальном `.env`.

4. Проверь, что сервер сообщил `Application startup complete` и не вывел ошибку запуска. Не показывай окно `.env`, значения ключа, пароль админки и личные уведомления.
5. Открой браузер и заранее подготовь вкладки:
   - `http://127.0.0.1:8000/docs` — Swagger;
   - форму заявки откроем из ответа API;
   - `http://127.0.0.1:8000/admin` — панель сотрудника.
6. Подготовь вымышленные данные из `examples/proposal_missing_fields.json`. Адреса используют домен `.example`. Не используй реальные данные разработчиков, компании или игры.
7. Для чистого кадра закрой лишние вкладки/уведомления, увеличь масштаб браузера до 110–125%, включи запись экрана с системным звуком только если это требуется. Подготовь учётные данные панели заранее, но не записывай их на видео.

## Видео 1 — демонстрация, 2–3 минуты

### 0:00–0:15 — задача

Скажи: «Покажу учебный сервис первичной обработки предложения об игре. Он переводит сообщение, сохраняет заявку и запрашивает недостающие данные через форму».

### 0:15–0:55 — API и анализ

1. Переключись на вкладку Swagger `/docs`.
2. Найди блок **POST /triage** и нажми на строку, чтобы раскрыть метод.
3. Нажми **Try it out**.
4. В редакторе JSON вставь содержимое `examples/proposal_missing_fields.json` (Ctrl+A → Ctrl+V).
5. Нажми **Execute**.
6. Покажи код ответа `201` и поля ответа: `category`, `business_type`, `text_ru`, `missing_fields`, `form_url` и `draft_reply`. Прокрути аккуратно, не задерживаясь на длинном JSON.
7. Скажи: «Название игры и студии сохраняются в оригинале; перевод хранится отдельно. Здесь не хватает контакта и ссылки на материалы».

Если появился `fallback`/эскалация, это допустимый сценарий при недоступности LLM: назови его резервным ответом и не утверждай, что сейчас сработал реальный перевод модели. Для показа анализа с LLM повтори запрос только если локальная конфигурация уже доступна; не раскрывай ключ.

### 0:55–1:35 — форма разработчика

1. Скопируй `form_url` из ответа и открой в новой вкладке.
2. Покажи, что известные поля студии, игры и страницы уже заполнены.
3. В поле email введи вымышленный адрес, например `demo@pine-lantern.example`.
4. В ссылку на материалы введи `https://materials.example.test/mist-sea`.
5. Нажми кнопку отправки формы.
6. Покажи подтверждение успешного сохранения.

### 1:35–2:15 — проверка сотрудником

1. Перейди на `/admin`.
2. Введи локальные `ADMIN_USER` и `ADMIN_PASSWORD`, не показывая ввод. Если появляется системное окно авторизации, начни запись после его закрытия либо обрежь этот фрагмент при монтаже.
3. Открой последнюю заявку. Покажи оригинал, русский перевод, данные игры, комментарий разработчика и статус проверки.
4. Заверши фразой: «После дополнения заявка остаётся на проверке сотрудника; сервис не принимает решение о сотрудничестве автоматически».

Если запись получается длиннее 3 минут, оставь в ролике успешный ответ API, форму и карточку сотрудника, сократив переходы.

## Видео 2 — защита проекта, 5–7 минут

Порядок выступления:

1. **Проблема и пользователь (40–60 сек.)** — входящие предложения приходят на разных языках и часто не содержат контакта или материалов; сотруднику нужно привести их к удобному виду.
2. **Границы MVP (40–60 сек.)** — один сценарий входящего предложения; реальная почта не подключена; форму отправляют вручную; инвестрешение принимает человек; финансовая Due Diligence относится к следующему проекту.
3. **Вход и контракт API (45–60 сек.)** — `POST /triage`, обязательные `text`, `channel`, `client_id`, валидация FastAPI/Pydantic.
4. **Архитектура (60–90 сек.)** — endpoint → LLM-анализ/перевод → проверка структуры → SQLite → ссылка на форму → заполнение разработчиком → ручная проверка сотрудником.
5. **Живой показ (1.5–2 мин.)** — повтори краткий путь Swagger → форма → карточка сотрудника из первого видео.
6. **Ошибки и надёжность (45–60 сек.)** — при ошибке модели сервис использует fallback и эскалирует; есть валидация, лимит запросов, журнал событий. Не заявляй автоматическую отправку писем.
7. **Риски и человеческий контроль (30–45 сек.)** — перевод, полноту и достоверность сведений проверяет человек; публичное размещение панели требует HTTPS и защищённой конфигурации.
8. **Что дальше (30–45 сек.)** — запрашивать LTV/ARPPU/retention/conversion и условия территориальных вариантов, формировать документ оценки для staff, инвесторов и маркетинга.

## Перед отправкой записи

- В кадре нет `.env`, API-ключей, пароля, личной почты, реальных материалов или переписок.
- Видны результаты фактических действий; не выдавай скриншоты за видеозапись и не называй неподтверждённые функции готовыми.
- Для первого видео длительность 2–3 минуты, второго — 5–7 минут (по требованиям задания).
- Загрузить видео в место, доступное проверяющему, и вставить ссылку в форму сдачи/отчёт только если этого требует куратор. Ссылку и сам факт загрузки мы пока не фиксируем: записи ещё нужно сделать.
